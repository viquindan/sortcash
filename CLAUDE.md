## Architecture

**Sortcash** ("Netflow Finance Dashboard") is a Next.js 14 App Router application for analyzing bank transactions imported from Latin American bank statements. It uses server components for data fetching, client components for interactivity, and Next.js API routes for mutations.

### Key Directories

- `app/(auth)/` — Public auth routes (sign-in, sign-up, forgot/reset-password)
- `app/(dashboard)/` — Protected routes (overview, transactions, averages, settings, import)
- `app/api/` — REST API routes for all mutations
- `lib/` — Business logic: DB, auth, parsers, categorization, caching, i18n
- `components/` — UI components; `components/ui/` for base elements, `components/charts/` for Recharts visualizations

### Data Flow

1. **Auth:** JWT via `jose`, stored in HttpOnly cookie (`session`, 7-day). `middleware.ts` verifies the JWT and guards all dashboard routes. Public paths are whitelisted in the middleware.
2. **Data fetching:** `lib/data.ts` uses `unstable_cache` with user-scoped tags (`txs-{userId}`, `cats-{userId}`, etc.). After any mutation, the API route calls `revalidateTag()` to invalidate.
3. **File import:** Client uploads a file → `POST /api/transactions` → `lib/parsers/index.ts` dispatches to CSV/Excel/PDF parser → bank detection → normalization → dedup by `externalId` → bulk insert.
4. **Categorization:** `lib/categorize.ts` applies Jaro-Winkler fuzzy matching (threshold 0.85) against hard-coded keyword rules and user-defined `categoryRules` from the DB.

### Database

Drizzle ORM with Neon's HTTP driver (not WebSocket). Schema in `lib/db/schema.ts`, 8 tables: `users`, `transactions`, `knownAccounts`, `uploads`, `categoryRules`, `merchantExclusions`, `customCategories`, `passwordResetTokens`.

Transactions are deduplicated by `userId + externalId`. The `externalId` is generated by the parser from the transaction date, description, and amount.

### File Parsers

All parsers live in `lib/parsers/` (not `lib/parsers.ts` — that file was removed). The dispatcher is `lib/parsers/index.ts`. Shared helpers `normalizeDate()` and `normalizeAmount()` handle Spanish date formats (`01-oct-2025`) and comma/dot decimal variants.

- **PDF parser** runs client-side using `pdfjs-dist`. The worker file must exist at `/public/pdf.worker.min.mjs`.
- **Banco General Excel** columns: Fecha, Descripción, Débito, Crédito, Saldo.
- **Banco General PDF** row format: `01-oct-2025 DESCRIPCION -$235.39 $3,077.59`.

### Categories

Hardcoded expense categories (Spanish): Transporte, Restaurantes, Supermercado, Entretenimiento, Salud, Vivienda, Transferencias, Efectivo, Compras, Otros.
Income categories: Salario, Renta de inmuebles, Rendimientos financieros, Devolución de compras, Otros ingresos.

User-defined rules and custom categories are persisted in the DB and merged at categorization time.

### i18n

`lib/i18n/translations.ts` + `lib/i18n/useLang.ts`. The dashboard UI is in Spanish; the landing page is in English.

## Environment Variables

Required in `.env.local` (dev) or server environment (prod):

```
DATABASE_URL="postgresql://..."   # Neon connection string
JWT_SECRET="..."                  # Min 32 random characters
NODE_ENV="production"
```
